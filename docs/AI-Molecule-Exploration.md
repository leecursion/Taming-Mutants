# AI 분자 탐색

시작 화면에서 **사례 탐색 / AI 분자 탐색**을 선택합니다. 사례 탐색은 기존 사건 진행을 유지합니다. AI 탐색에서는 채팅 또는 기존 음성 입력으로 요청하며, 구조는 Unity의 실제 메시로 표시합니다. 마우스 드래그로 회전하고 휠로 확대합니다. 좌하단 버튼으로 리본/원자 보기를 바꾸고 우하단에서 모드를 나갑니다. 사례 탐색에서도 같은 우하단 **모드 선택** 버튼으로 나갑니다. 이 버튼은 사건을 고를 수 있는 동안에만 보이며, 사건 안으로 들어가면 같은 자리에 기존 `StructureLevelBackButton`의 '이전'이 섭니다.

## 배경 전환

AI 분자 탐색으로 들어갈 때 사건을 골랐을 때와 같은 배경 전환이 재생됩니다. 새로 만든 연출이 아니라 기존 `CameraTransitionDirector`의 같은 경로(연구실 `Level0_Body` → `IntroDirector.explorationLevel`, 기본 `Level2_Protein`)를 그대로 지나가므로, 여기에 딸린 워프 파티클·모션 블러·음향(`TransitionEffects`)과 트랜지션 중 비서 감추기(`QuestLevelBinder`)도 함께 붙습니다. **모드 선택**을 누르면 사건을 접고 나올 때와 같은 후퇴 연출(`SpatialZoomOut`)로 연구실 시점으로 돌아옵니다.

- 사건의 단백질 무대는 계속 꺼둔 채입니다. `HideStage`만 호출하면 카메라 전환 중 `LevelStage.SetActive(true)`가 사건 구조와 진입 이벤트를 다시 켤 수 있으므로, AI 탐색은 `CameraTransitionDirector.GoToCameraOnly`로 이동합니다. 카메라·전환 효과는 재사용하고 사건 도메인 및 `onEnter`는 활성화하지 않습니다. 사례 탐색은 기존 `GoTo`를 사용합니다.
- 구조는 카메라 앞 고정 거리에 한 번만 놓이므로, 진입 연출이 끝난 뒤에 세웁니다. 날아가는 중에 놓으면 도착 후 화면 밖에 남습니다.
- 퀘스트 보드도 카메라 이동이 끝난 뒤 펼칩니다. 탐색에서 빠져나오자마자 사례 탐색을 고르면 아직 후퇴하는 중일 수 있습니다.
- 씬에 `CameraTransitionDirector`가 없으면 전환 없이 기존 동작 그대로입니다.

## 요청 처리

**설정된 LLM이 모든 텍스트·음성 요청을 먼저 해석합니다.** 대표 이름 사전은 자연어 서버가 전혀 설정되지 않은 오프라인 환경에서만 사용합니다. 서버 실패를 이름 사전 성공으로 숨기지 않습니다.

1. Unity가 요청과 현재 구조의 이름, PDB ID, 표시 체인, 실제 존재하는 체인·잔기 범위·리간드를 전송합니다.
2. LLM이 검색, 표시 변경, 확대, 회전, 설명, 명확화 중 동작을 결정합니다.
   세포·조직처럼 단일 PDB 분자가 아닌 요청에는 렌더링 가능한 대표 단백질 2~3개를 질문으로 제시합니다. Unity는 최근 질문과 답변을 보관하므로 사용자가 `CD4`, `두 번째`, `사람 것`처럼 짧게 답해도 앞선 선택 문맥과 함께 해석합니다.
3. 새 검색이면 이름·동의어·유전자 기호를 OR 검색합니다. 결과가 없으면 전문 검색으로 한 번 확장합니다. 명시한 생물종·상태 조건을 제거하지 않습니다.
4. RCSB Data API에서 후보의 실제 이름·종·체인·서열 길이·변이·엔트리 제목·리간드·해상도를 수집합니다.
5. LLM이 이 후보들을 비교해 적합한 구조를 선택합니다. 단순히 검색 첫 결과를 선택하지 않습니다. 변이·결합 상태 등 조건이 있으면 제공된 메타데이터의 근거를 함께 요구합니다. 근거가 없거나 존재하지 않는 ID를 반환하면 해당 구조를 표시하지 않습니다.
6. Unity가 반환된 구조·선택 범위를 실제 좌표에 대조하고 표시 예산 안에서 렌더링합니다. 성공 후에만 완료를 안내합니다.

예시:

- `혈당을 조절하는 단백질 보여줘` → 기능을 해석해 대표 구조 선택.
- `어떤 분자를 추천하나요?`, `처음 보는 사람인데 뭘 보면 재미있을까요?` → 입문용 단백질 후보와 역할을 제안. 이어서 `첫 번째 것으로 보여줘`처럼 번호로 선택하면 검색·표시로 연결. 사용자가 고르는 대신 직접 골라 보여달라고 하면 대표 구조를 선택하도록 해석.
- `그것들 말고 소화 관련 단백질을 추천해줘` → 이전 후보와 관심사를 참고해 새로운 후보를 제안. `첫 번째를 왜 추천했어?` → 구조를 아직 표시하지 않았어도 추천 이유를 설명하고 선택지는 유지. 이어서 `첫 번째 것으로 보여줘` → 해당 후보 검색·표시.
- `백혈구 보여줘` → CD4·T세포 수용체·항체 등의 선택 질문. 이어서 `CD4`라고 답하면 CD4 구조 검색.
- `사람 알부민`, `닭 라이소자임` → 생물종을 유지하는 검색.
- `산소가 붙은 헤모글로빈` → 처음부터 거부하지 않고 상태 조건으로 검색·후보 비교. 검색된 메타데이터에 근거가 있어야 표시.
- `이거 원자 하나하나 보이게 해줘` → 현재 구조의 원자 보기.
- `나선 부분만`, `시트 부분만` → 기존 2차 구조 판정으로 해당 리본 부분만 표시.
- `B 체인만`, `50~80번만` → 존재하는 체인·잔기 범위로 선택. 잔기 하나는 원자로 표시.
- `헴만 남겨줘` → 현재 구조의 해당 리간드 인스턴스 하나 표시.
- `더 크게`, `오른쪽으로 돌려줘` → 현재 구조를 조작.
- `전체로 돌아가줘` → 선택 범위를 초기화하되 표시량 제한은 유지.

LLM 해석은 실제 모델 응답에 따라 달라질 수 있습니다. 사용자 표현을 키워드 목록에 계속 추가하는 방식이 아니라, 동일한 구조화 명령으로 해석하도록 설계했습니다.

## 연결 설정

### 추천은 고정 메뉴가 아닙니다

탐색 진입 시 인슐린·헤모글로빈·GFP를 매번 읽던 안내를 없앴습니다. 온라인 LLM 프롬프트에서도 세 단백질의 목록과 우선 추천 지시를 제거했습니다. 모델은 관심사, 앞선 대화, 제외한 후보를 참고해 단백질을 제안하고, 선택한 이름으로 RCSB를 검색합니다. 내장 세 구조는 오프라인 예시와 다운로드 실패 시의 대체 좌표이며 온라인 추천 범위를 제한하지 않습니다.

실제 모델 검증에서 일반 추천에 DNA 중합효소, 입문자 추천에 ATP 합성효소가 포함됐습니다. 기존 세 분자를 제외하고 소화 관련 단백질을 요청하자 펩신·트립신·아밀레이스를 제안했고, 추천 이유를 설명한 뒤 번호 선택으로 펩신 `3UTL`의 `load` 응답까지 이어졌습니다. 추천 이름은 매번 달라질 수 있고, 큰 복합체 등은 좌표 검색·표시 한도 검사에서 표시되지 않을 수 있습니다.

`Check-LiveResolver.mjs --local --diverse`는 일반 추천 → 다른 소화 관련 후보 → 추천 이유 → 번호 선택의 실제 API 흐름을 검사합니다. 결과는 `Temp/ExplorationChecks/diverse-local.json`입니다. 이 파일이 있으면 Unity smoke 테스트가 해당 검색 결과를 우선 렌더링합니다.

- **Unity 변경과 Worker의 `/api/molecule-resolve` 변경을 함께 반영해야 합니다.** 이전 Worker가 계속 배포되어 있으면 새 동작·후속 요청 해석은 적용되지 않습니다.
- 서버는 기존 `UPSTAGE_API_KEY`와 `solar-pro4`를 사용합니다. Unity에 새 LLM 키를 넣지 않습니다.
- `AICoScientistClient.backendEndpoint`가 설정되어 있으면 같은 서버의 `/api/molecule-resolve`와 기존 `proxyToken`을 자동 사용합니다.
- 별도 서버는 IntroDirector 오브젝트의 `MoleculeExplorationController.resolverEndpoint`와 `proxyToken`으로 설정합니다. 컴포넌트가 없으면 런타임에 자동 추가됩니다.
- `SolarChatClient` 직접 연결만 사용하는 환경은 검색 Worker URL을 별도로 설정해야 합니다. 기존 사례용 프롬프트와 분자 제어용 JSON 프롬프트는 분리됩니다.
- 음성은 기존 STT·마이크 권한을 재사용합니다. 서버 인증은 기존 `APP_TOKEN` / `X-App-Token` 정책입니다.
- 연결이 없으면 `인슐린`, `사람의 헤모글로빈`, `GFP`의 기본 이름과 간단한 리본/원자 명령만 오프라인 대체 동작을 합니다. 이 경로는 LLM 추론이 아닙니다.

## 실제 표시 범위

### 검색 실패와 후속 질문 확인

- 채팅에 띄어쓰기를 입력할 때 EGFR·858번 잔기·pLDDT 설명이 갑자기 나오던 원인은 씬에 남아 있던 `AIAssistantStateTester`의 Space 예시 대사였습니다. 이제 `enableTestShortcuts`를 명시적으로 켜야 테스트 단축키가 동작하며, 켜더라도 채팅 입력 중 또는 AI 분자 탐색 중에는 Space와 숫자 1~5를 처리하지 않습니다. 이 예시 대사는 검색 결과나 실제 표시 구조에 대한 설명이 아닙니다.

- 이전의 `지원하지 않는 구조 식별자 또는 표시 범위입니다.`는 Unity가 서버의 `spec.pdbId` 또는 `spec.chains` 형식을 거부했다는 뜻입니다. 실제 서버 응답이 없으면 둘 중 어느 값이 잘못됐는지 단정할 수 없습니다.
- 이제 PDB ID 앞뒤 공백과 대소문자, 체인 목록의 쉼표 주변 공백 및 중복을 정리합니다. ` 4hhb `와 ` A, B `는 각각 `4HHB`, `A,B`로 처리합니다. 체인 대소문자는 서로 다른 체인이므로 유지합니다.
- 잘못된 ID·체인·잔기 범위는 구분해 재질문을 안내합니다. 개발용 Console의 `[AI 분자 탐색] Invalid resolver selection`에서 반환값을 확인할 수 있습니다. 표시 실패도 최근 대화에 포함하므로 다음 요청에서 실패를 참고할 수 있습니다.
- 현재 구조 문맥은 **실제 표시 성공 후** 만들어집니다. 검색이 실패해 아직 표시한 분자가 없다면 `이것을 설명해줘` 대신 단백질 이름이나 실패 안내에 대한 답변으로 다시 검색해야 합니다. 기존 구조가 있었다면 실패 후에도 그 구조가 유지됩니다.
- 연결 설정을 반영한 뒤 `인슐린 보여줘` → 표시 완료 → `B 체인만` → `이 부분을 설명해줘` 순서로 확인합니다. 선택 질문은 `백혈구 보여줘` → 비서가 제시한 단백질 이름으로 답변하는 흐름으로 확인합니다.
- 오프라인 이름 사전만으로는 자연어 후속 질문이 작동하지 않습니다. 최신 Worker의 `/api/molecule-resolve`, `UPSTAGE_API_KEY`, 일치하는 `APP_TOKEN`/`proxyToken`이 필요합니다. Worker 소스 변경은 로컬 Unity 재생만으로 배포되지 않으며 `server`에서 `npm run deploy`로 별도 반영합니다.

대표 구조는 1TRZ(사람 인슐린 A·B), 4HHB(사람 산소 비결합 헤모글로빈 A와 헴), 1EMA(GFP A)입니다. 온라인 좌표 요청 실패 시 이 세 항목은 내장 좌표를 사용할 수 있습니다. 최근 3개 구조를 메모리에 캐시합니다.

- **데스크톱 400잔기 / 상세 원자 320개, 모바일 240잔기 / 180개** 한도는 언어 해석과 별개로 유지합니다.
- 체인이나 잔기 범위를 먼저 선택한 뒤 한도를 적용합니다. 리간드를 지정하면 그 주위 잔기를 우선 표시합니다.
- 원자 상세는 표시할 단백질 부위와 리간드 주위 원자를 가까운 순으로 제한합니다. 완전한 결합 포켓 전체를 보장하는 선택은 아닙니다.
- 실제 존재하지 않는 체인·범위·리간드는 오류를 알리고 기존 모델을 유지합니다. 새 모델은 완성 후 교체됩니다.
- 리본은 기존 BackboneChain / SecondaryStructureAssigner / RibbonMeshBuilder를 재사용합니다. 원자·결합·리본은 메시를 합쳐 오브젝트 수를 줄입니다. 결합은 제한된 원자 집합의 거리 기반 시각화입니다.
- 파일 한도 8 MiB, 수소·물 제외 최대 60,000원자. 검색 후보도 엔트리의 원자 수가 이 범위를 넘으면 제외합니다. NMR은 첫 모델만, altloc는 공백/A를 사용합니다.
- 런타임은 legacy PDB 포맷입니다. mmCIF-only 대형 구조와 확장 PDB ID, 결정학적 전체 조립체 재구성은 아직 지원하지 않습니다.
- **자유 소분자·DNA/RNA 렌더러는 아직 연결되지 않았습니다.** 단백질에 결합한 리간드는 표시할 수 있습니다. 이 기능 차이는 프롬프트 완화만으로 해결하지 않습니다.
- 명명된 도메인은 해당 도메인 구조라는 메타데이터 근거가 있는 후보를 검색할 수 있지만, 도메인 이름만으로 임의의 잔기 번호를 만들어 자르지 않습니다. 명시한 숫자 범위 선택은 지원합니다.
- 실험 B-factor를 AlphaFold pLDDT로 표시하지 않습니다. 기기별 FPS 보장이나 분자 동역학 시뮬레이션 기능은 아닙니다.

## 검증

### 2026-09-15 실제 모델 연결 확인

씬에 설정된 배포 서버에서는 `혈당을 낮춰주는 물질`, `백혈구`에 대해 `action` 없이 지원하지 않는다는 `message`만 반환했습니다. 로컬의 대화형 resolver와 다른 동작이며, 로컬 수정만으로 이 서버의 응답이 바뀌지는 않습니다.

로컬 최신 resolver를 개발용 키로 실제 Solar와 RCSB에 연결해 다음을 확인했습니다.

- `혈당을 낮춰주는 물질을 보고 싶어` → 인슐린 검색 → `1EV3`, 체인 B 선택.
- `백혈구 보여줘` → CD4 / T-cell receptor / Antibody 선택 질문 → `첫 번째 것으로 보여줘` → CD4 검색 → `1CDJ`, 체인 A 선택.
- PDB ID와 제안 목록은 모델과 검색 결과에 따라 달라집니다. 위 기록은 고정 이름 사전이나 모의 LLM 결과가 아닙니다.

실제 응답에서 발견한 문제도 수정했습니다: 질문 단계의 빈 `view`를 기본값으로 처리하고, 후보 선택 JSON이 잘못되면 같은 후보·문맥으로 한 번 재요청합니다. 선택지 전체를 같은 순서로 표시하고 `pendingChoices`로 다음 요청까지 전달합니다. 후보 순위를 정하는 모델에도 해석한 단백질 이름과 대화 기록을 전달합니다.

추가 추천 질문 검증: 배포 서버는 `어떤 분자를 추천하나요?`를 지원하지 않는다는 응답으로 거부했습니다. 추천 요청을 명시한 로컬 resolver는 실제 모델에서 인슐린·헤모글로빈·GFP를 제안했고, `첫 번째 것으로 보여줘`에 `1TRZ`/A·B 체인의 `load` 응답을 반환했습니다. `처음 보는 사람인데 뭘 보면 재미있을까요?`도 세 후보를 제안했습니다. 이 검증은 `Check-LiveResolver.mjs --recommendations`(배포 서버) 또는 `--local --recommendations`(로컬 코드 + 실제 모델)로 재실행할 수 있으며, 결과 파일은 `recommendations-deployed.json`/`recommendations-local.json`입니다.

재검증 도구: `node Tests/Exploration/Check-LiveResolver.mjs`는 씬의 배포 서버를, `--local` 옵션은 `server/.dev.vars`의 개발용 키로 로컬 resolver와 실제 API를 확인합니다. 실제 API 호출이 발생합니다. 연결 키는 출력하지 않습니다. 결과는 `Temp/ExplorationChecks/live-resolver.json` 또는 `live-local-resolver.json`에 저장됩니다. 이 로컬 결과가 존재하면 Unity smoke 테스트는 선택된 PDB도 내려받아 실제 메시 생성 여부를 검증합니다.

- `cd server` → `npm test`: 입력 해석·후보 선택·조건 근거·현재 구조 명령 테스트 및 기존 구술 평가 회귀 테스트. LLM 응답은 모의 응답이며 유료 모델의 모든 표현에 대한 정확도를 보장하지 않습니다.
- `Tests/Exploration/Prepare-Smoke.ps1`: 별도 Unity 테스트 프로젝트 준비. 출력된 batch 명령으로 실제 메시 생성과 UI/텍스트 연결을 검증합니다. 테스트용 SceneDependencies.cs는 실제 Assets에 넣지 않습니다.
- 결과는 `Temp/ExplorationChecks/Unity/smoke-result.txt`, `smoke-details.txt`, PNG들에 저장됩니다.
