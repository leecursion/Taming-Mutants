# AI 분자 탐색의 반복 도킹 실험

사용자가 선택한 단백질에 소분자 후보를 하나씩 불러와 실제 AutoDock Vina 도킹을 실행합니다. 후보를 바꿔도 **단백질·도킹 부위·완료된 실험 기록**이 유지됩니다. 기존 사례 퀘스트의 미리 정해진 `outcome`/`affinity`는 사용하지 않습니다.

## 사용 순서

1. **AI 분자 탐색**에서 원하는 단백질을 말하거나 검색합니다. 진입 시 비서가 추천 요청 방법을 안내합니다. 이름을 모르면 기존 비서 마이크나 채팅으로 단백질을 추천해 달라고 요청하고 제안된 카드를 선택합니다.
2. 화면 왼쪽 위 **도킹 실험**을 엽니다.
3. **후보 선택**에서 현재 구조에 포함된 리간드 카드를 고르거나 **후보 추천**으로 받은 카드를 선택합니다. 기존 리간드는 RCSB CCD, 추천 후보는 PubChem에서 실제 화학 구조를 조회합니다. 이전에 불러온 후보도 카드로 다시 선택할 수 있습니다. 출처와 후보 이름을 확인합니다. 주황색 후보는 **도킹 전 미리보기**입니다.
4. **부위 선택**에서 `STI 주변 · A:201`처럼 구조에 포함된 리간드의 위치 카드를 고릅니다. 청록색 상자가 실제 계산할 영역이고 카메라가 이 부위를 확대합니다. 기존 리간드가 없으면 부위를 말하거나 **직접 입력 / 고급**에서 `A:123-130` 같은 실제 잔기 범위를 지정합니다. LLM이 포켓 좌표를 만들어 지정하지 않습니다.
5. **도킹 실행**을 누릅니다. 계산 중에는 부위 스캔이 표시됩니다. 실제 결과를 받은 뒤 녹색 후보가 계산된 좌표로 이동하고 점수(kcal/mol)와 가까운 잔기를 보여줍니다. **다음 자세**로 최대 5개의 예측 자세를 확인합니다.
6. **다른 후보 실험**을 누르고 새 후보 카드를 선택한 뒤 다시 **도킹 실행**합니다. 단백질과 부위, 이전 실험 기록은 유지됩니다. 원하는 후보가 없으면 **후보 추천**, 기존 비서 마이크, 직접 입력 중 하나를 사용합니다.
7. **실험 기록**의 결과 카드를 선택해 이전 자세와 점수를 다시 봅니다. **AI와 결과 비교**로 실제 점수·비교 조건을 전달해 토론합니다. 기록을 보는 행위는 다음 실험 후보를 바꾸지 않습니다. 위 후보 표시가 다음 실험 대상입니다.

**직접 입력 / 고급**에는 영문/한국어 이름, `CID 2244`, `SMILES:CC(=O)Oc1ccccc1C(=O)O`, SDF 경로를 입력할 수 있습니다. 기본 카드 화면에서는 입력란이 숨겨져 있습니다. 음성 요청은 기존 비서 마이크에서 녹음을 시작하고 다시 눌러 전송합니다. 별도의 하단 추천·음성 버튼은 제공하지 않습니다. 음성 기능은 기존 STT 백엔드와 마이크 설정이 필요합니다.

연출은 계산 상태와 반환된 자세를 보여주는 화면 효과입니다. 이동 경로는 분자동역학 궤적이 아니며, 노란 잔기 표시는 중원자 거리 4 Å 이내의 근접 표시입니다. 이펙트가 점수나 결합 판정을 만들지 않습니다.

### 입체형 선택과 실패 후 진행

입체형이 지정되지 않은 후보는 **입체형 카드**를 제공합니다. 카드의 원자 번호별 R/S 표시와 입체형 SMILES를 보고 선택하면 해당 구조를 생성하고 도킹을 진행할 수 있습니다. 기존에 지정된 입체중심을 유지하며 미지정 부분의 가능한 형태를 최대 8개 제시합니다. 이 선택지는 RDKit이 생성한 구조 후보이며, 실험으로 확인된 입체형이나 새 PubChem CID가 아닙니다. 알고 있는 정확한 CID/SMILES도 직접 입력할 수 있습니다.

| 상황 | 화면에서 가능한 대응 |
|---|---|
| 후보 조회·구조 준비 실패 | 상세 원인 확인, 불러오기 재시도, 다른 후보 선택, **이전 후보로 계속** |
| 입체형 미지정 | 입체형 카드 선택 또는 정확한 CID/SMILES 입력 |
| 잔기 없음·부위가 너무 넓음 | 부위 다시 선택, 고급 입력에서 좁은 범위 지정, **이전 부위로 계속** |
| 계산 실패 | 원인과 실패 기록 확인 후 후보·구조·부위 재검토. 결합 불가 판정으로 표시하지 않음 |
| 점수가 0 이상 | 해당 계산 조건에서 유리한 점수가 나오지 않았음을 안내. 결합 불가를 확정하지 않음 |

후보나 부위 선택에 실패하면 이전 데이터는 보존하지만, 그 상태로 이전 선택이 자동 실행되지는 않습니다. 새 선택을 완료하거나 이전 선택으로 계속할 것을 명시적으로 눌러야 합니다. 후보·부위를 바꿔도 원자 상세 보기는 유지하며, 리간드만 보기에서 부위를 선택하면 단백질을 볼 수 있도록 원자 보기로 전환합니다.

검색창은 도킹 패널의 실제 하단 위치를 기준으로, 겹치지 않을 만큼만 아래로 조절합니다. 패널을 닫으면 원래 검색창 높이로 돌아갑니다. 도킹 부위는 화면 중앙, 비서와 말풍선은 오른쪽 공간에 배치합니다.

탐색 상자는 **부위 선택 / 고급 설정에서 부위를 확인할 때만** 표시합니다. 후보·기록 탭으로 이동하거나 패널을 닫으면 숨기고, 계산 중과 완료된 결과에서도 숨깁니다. 실제 계산에 사용하는 영역 좌표는 유지됩니다. 다시 부위를 선택하면 상자가 나타납니다.

패널은 선택된 탭, 카드 제목·보조 설명, 주요 실행 버튼을 구분합니다. 과거 결과는 **실험 기록 카드**로 선택하며 중복된 이전·다음 기록 버튼은 제거했습니다. **다음 자세**는 결과가 표시될 때만 나타납니다.

계산된 자세를 표시할 때는 파란 부위 원과 스캔도 숨깁니다. 과거 결과나 다른 자세를 다시 열어도 파란 원은 나타나지 않으며, 결과 분자와 노란 근접 잔기 표시는 유지됩니다.
**다른 후보 실험**으로 넘어가거나 후보를 다시 불러와도 파란 원은 숨긴 상태를 유지합니다. 부위 선택·고급 설정에서 부위를 확인하거나 실제 계산이 진행 중일 때만 표시하고, 패널을 닫으면 숨깁니다.

후보 로딩 실패 시 기존 후보와 기록이 유지됩니다. 계산 실패도 기록되고 다음 후보를 시도할 수 있습니다. 실행 중에는 후보/부위 변경을 막고 **취소**를 제공합니다. 채팅·회전·표시 방식 변경은 계산을 취소하지 않습니다. 단백질이나 선택 체인을 바꾸거나 모드를 나가면 진행 중인 계산을 취소하고 현재 세션을 초기화합니다.

완료/실패한 실험 JSON은 `Application.persistentDataPath/DockingExperiments/<sessionId>/<jobId>.json`에 저장됩니다. 후보 SDF/SMILES/CID, PDB ID·체인, 부위 좌표, 예측 자세, 점수, 엔진 설정, 수용체 좌표 해시가 포함됩니다. UI 기록은 현재 세션의 최근 20개이며, 저장된 JSON을 다음 세션 UI로 다시 불러오는 기능은 아직 없습니다.

### SDF 파일

데스크톱에서는 후보 입력에 `file:D:\Molecules\candidate.sdf`처럼 절대 경로를 입력할 수 있습니다. 파일은 200 KB 이하이며 단일 분자여야 합니다. 모바일/XR에서는 접근 가능한 파일 경로가 제한되므로 이름·CID·SMILES 입력을 사용합니다. OS 파일 선택 창은 제공하지 않습니다.

## 개발 PC에서 실행 (Windows)

프로젝트 루트에서:

```powershell
./Tests/Docking/Start-LocalDocking.ps1
```

Python 3.12와 Node.js가 필요합니다. 스크립트가 `Temp/DockingEnv`에 의존성을 설치하고 공식 Vina 1.2.7 실행 파일을 내려받습니다. CPU 서비스(8000)와 로컬 Worker 프록시(8791)를 127.0.0.1에만 실행합니다. 로그·프로세스 정보는 `Temp/DockingChecks`에 남습니다.

Unity Editor는 생성된 `Temp/DockingChecks/editor-service.json`을 읽습니다. Inspector의 명시적 `dockingEndpoint`/`resolverEndpoint`는 우선합니다. 씬이나 빌드용 서버 주소를 수정하지 않습니다.

- `server/.dev.vars` 또는 환경 변수에 `UPSTAGE_API_KEY`가 있으면 최신 로컬 resolver도 연결됩니다. 한국어 후보 이름·음성 도킹 명령·실험 결과 토론을 실제 Solar로 해석합니다.
- 키가 없으면 기존 단백질 검색 서버를 유지하고 도킹 패널에서 영문 이름·CID·SMILES·SDF로 실제 계산할 수 있습니다. 한국어 후보 이름은 영문 이름/CID 입력 안내로 응답합니다. 기존 배포 Worker가 새 도킹 동작을 지원하지 않으면 채팅 도킹 명령은 동작하지 않습니다.
- API 작업 상태는 단일 Uvicorn 프로세스의 메모리에 있고 재시작하면 소실됩니다. Unity에 이미 전달된 결과와 저장된 JSON은 유지됩니다.

종료:

```powershell
./Tests/Docking/Start-LocalDocking.ps1 -Stop
```

로컬 연결 파일도 제거되므로 기존 서버 설정으로 돌아갑니다. 프로세스가 비정상 종료되어 연결 파일이 남았을 때도 `-Stop`을 실행합니다.

## 서버 배포

`server/docking`의 Python 서비스는 기존 Worker와 함께 **Cloudflare Containers**로 배포합니다. `server/wrangler.toml`의 `[[containers]]`가 `docking/Dockerfile`을 가리키고, Worker는 `DOCKING` Durable Object 바인딩(`src/docking-container.js`)을 통해서만 컨테이너를 호출합니다. 컨테이너에는 공개 주소가 없습니다.

요구 사항:

- Cloudflare **Workers Paid** 플랜 (Containers는 Free 플랜에서 동작하지 않음)
- 로컬 **Docker** 데몬 실행 중 — `wrangler deploy`가 이미지를 빌드해 Cloudflare 레지스트리에 올립니다

```powershell
cd server
npx wrangler deploy
```

인스턴스는 `max_instances = 1`, `standard-3`(2 vCPU, `chemistry.py`의 `vina --cpu 2`와 맞춤)이며 유휴 15분 후 잠듭니다. 작업 상태는 프로세스 메모리에 있으므로 잠든 뒤에는 이전 작업을 조회할 수 없고, 잠에서 깨는 첫 요청은 컨테이너 기동 시간만큼 느립니다. `DOCKING_SERVICE_TOKEN` secret을 넣으면 컨테이너에도 같은 값이 전달되어 토큰 검사가 켜지지만, Worker→컨테이너 구간은 외부에 열려 있지 않아 필수는 아닙니다. 기존 `APP_TOKEN`, `UPSTAGE_API_KEY`는 그대로 유지합니다.

Worker 코드만 다시 올리고 컨테이너 이미지는 건드리지 않으려면 `npx wrangler deploy --containers-rollout=none`을 씁니다(Docker 불필요).

`DOCKING` 바인딩이 없는 환경(로컬 `wrangler dev`, `Tests/Docking/Start-LocalDocking.ps1`)에서는 `DOCKING_SERVICE_URL`의 별도 프로세스를 호출하는 이전 경로가 그대로 동작합니다. 다른 호스트에 직접 띄울 때도 같은 Dockerfile을 쓸 수 있습니다:

```sh
docker build -t taming-mutants-docking server/docking
docker run --rm -p 8000:8000 -e DOCKING_SERVICE_TOKEN taming-mutants-docking
```

Unity는 기존 `AICoScientistClient.backendEndpoint` 또는 `resolverEndpoint`의 동일 서버 `/api/docking`을 자동 사용합니다. 직접 연결은 `MoleculeExplorationController.dockingEndpoint`와 `dockingToken`을 지정합니다.

## 자연어 동작과 결과 설명

최신 resolver의 추가 동작:

| 요청 예 | 동작 |
|---|---|
| `도킹 후보를 추천해줘` | `candidate_choices`, 선택 카드 제공; 번호 선택도 후보 로더로 연결 |
| `아스피린을 후보로 불러줘` | `load_ligand`, 영어 검색 이름으로 실제 PubChem 조회 |
| `이번에는 카페인으로 해보자` | 후보 교체, 단백질·부위·기록 유지 |
| `A 체인 123~130번에서 도킹하자` | `docking_site`, 실제 잔기 검사 |
| `이 후보를 도킹해줘` | `dock`, 현재 후보와 부위로 계산 |
| `두 후보의 결과를 비교해줘` | `explain`, 실제 실험 문맥을 전달 |

새 후보를 불러오면서 바로 도킹하라는 복합 요청은 먼저 후보를 불러옵니다. 확인 후 도킹 실행 버튼 또는 실행 명령으로 계산합니다. LLM에 최근 5개 실험, 선택 후보, 현재 표시 중인 과거 결과/자세, 원본 단백질과 중원자 거리 4 Å 이내의 잔기를 전달합니다. 이 거리 목록을 수소결합 판정으로 표시하지 않습니다.

## 계산 조건과 지원 범위

### 계산 실패와 연결 실패 구분

사용 중 실패한 `8VCX` D 체인을 실제로 재현했습니다. 서버 연결은 정상이었으며, 원본 PDB의 REMARK 470에 누락 원자가 명시되어 있고 Meeko 전처리가 D:2, D:17 등을 포함한 33개 잔기를 처리하지 못했습니다. 현재는 해당 잔기와 원자 누락/형식 불일치 원인을 표시합니다. 이 구조를 계산하려면 누락 원자 보완 또는 원자가 완전한 같은 단백질의 다른 PDB 선택이 필요합니다. 원자 보완 모델링은 현재 지원하지 않습니다.

전처리 오류, Vina 실행 파일 누락, 계산 시간 초과, 외부 분자 데이터베이스 연결 실패를 구분해 안내하고 상세 진단을 서버 로그에 남깁니다. 재현 검사는 `Temp/DockingEnv/Scripts/python.exe Tests/Docking/check_preparation_failure.py`입니다.

검색 요청 중 동일한 요청이 다시 들어오면 중복 실행하지 않습니다. 로딩 단계별 반복 음성을 제거했고, 도킹 부위 초점 조정용 내부 렌더링은 별도 음성을 내지 않습니다.

- 단백질–소분자의 고정 수용체·비공유결합 도킹입니다. 공유결합, 단백질–단백질, DNA/RNA 도킹은 지원하지 않습니다.
- 수용체는 화면에서 자른 메시가 아닌 내려받은 원본 PDB의 선택 체인 전체입니다. 첫 모델, altloc 공백/A를 사용하며 원본 좌표를 이동시키지 않습니다. UI의 회전·스케일과 도킹 결과는 동일한 좌표 변환을 거칩니다.
- 물·이온·기존 리간드(HETATM)는 계산에서 제외합니다. 금속·보조인자가 필수인 결합을 이 모델로 재현하지 않습니다.
- Meeko의 엄격한 잔기 템플릿으로 수소/원자 유형을 준비합니다. 누락된 중원자·인식하지 못하는 잔기를 조용히 삭제하지 않고 전처리 실패를 알립니다. 누락 루프 재구성이나 단백질 유연성 계산은 하지 않습니다.
- 리간드는 PubChem/RCSB CCD의 구조 또는 입력 SDF/SMILES의 결합·전하·입체형을 사용합니다. 3D 좌표가 없으면 RDKit ETKDG로 생성합니다. pH별 프로톤화/토토머 상태를 자동 탐색하지 않습니다. 염·혼합물과 지원하지 않는 원소는 거부하며, 미지정 사면체 입체형은 선택 카드를 제공합니다.
- 수용체 10~20,000 ATOM 레코드, 리간드 중원자 3~120개/회전 결합 최대 20개. 탐색 상자는 부위 주변에 6 Å씩 여유를 두며 각 변 20~30 Å입니다. 너무 큰 부위는 잘라 계산하지 않고 재선택을 요청합니다.
- Vina 1.2.7, Meeko 0.7.1, `seed=42`, `exhaustiveness=8`, CPU 2개, 최대 5개 자세. 계산 프로세스는 시간 제한이 있고, 최대 4개 작업을 수락하여 순차 계산합니다. 최대 32개 작업 결과를 보관하고 완료 후 한 시간이 지난 결과는 새 작업 수락 시 정리합니다.
- 동일한 수용체 해시·탐색 상자·계산 설정에만 같은 비교 키를 부여합니다. 점수를 실측 결합력·약효·성공 판정으로 바꾸지 않습니다.

## 검증

- `cd server; npm test`: 기존 resolver/구술 평가와 도킹 라우팅, 별도 서비스 토큰, 한국어 이름 변환 스키마 검사. LLM 응답은 모의 응답입니다.
- `cd server/docking; ../../Temp/DockingEnv/Scripts/python.exe -m unittest -v test_docking`: 좌표/체인/범위 검증, 실제 RDKit 분자 준비, 작업 재시도·취소·다음 후보·세션 분리 검사.
- `Temp/DockingEnv/Scripts/python.exe Tests/Docking/check_live.py`: 실행 중인 로컬 CPU 서비스에서 실제 PubChem 조회 및 실제 Meeko/Vina 계산. `Temp/DockingChecks/1IEP.pdb`가 필요합니다.
- `node Tests/Docking/check_live_commands.mjs`: 로컬 프록시의 실제 Solar로 한국어 후보 선택/교체, 실행, 잔기 부위 지정, 결과 비교 및 한국어 이름의 PubChem CID 확인. 개발용 키와 앞선 실제 도킹 결과가 필요합니다.
- `Tests/Exploration/Prepare-Smoke.ps1` 후 안내된 Unity batch 실행: 기존 탐색 회귀 검사와 후보 교체, 실패 시 상태 보존, 이전 세션 응답 차단, 실제 Vina 자세 메시, 기록/자세 버튼, 회전 좌표 변환, 모드 종료 정리 검사.
- 로컬 서버 실행 후 `$env:DOCKING_LIVE_UNITY='1'`을 설정하고 Unity batch를 실행하면 Unity가 직접 두 후보를 내려받고 실제 계산까지 순서대로 실행합니다. 이 경로도 통과했으며 `docking-http-smoke.txt`에 결과를 남깁니다.

2026-09-15 실제 계산: `1IEP` 체인 A, 중심 `[15.19, 53.903, 16.917]`, 크기 `[20,20,20]`에서 aspirin(CID 2244) → caffeine(CID 2519)을 순서대로 실행했습니다. 각각 최상위 점수 −7.109, −5.891 kcal/mol과 5개 자세가 반환됐으며, 두 번째 계산 후 첫 결과를 그대로 다시 조회했습니다. 이 수치는 해당 검증 조건의 계산 결과입니다.

같은 날 실제 Solar가 한국어 요청을 `load_ligand`(aspirin/caffeine), `dock`, `docking_site`로 해석했고, 두 실제 점수에 근거한 `explain`을 반환했습니다. 후보 입력 `아스피린`도 PubChem CID 2244 구조로 연결됐습니다. 결과는 `Temp/DockingChecks/live-commands.json`입니다.

추가 UI 검증: 후보/부위/과거 결과 카드 선택, 기본 입력란 숨김, 부위 화면 위치, 실제 계산 중 스캔, 계산 완료 후 이동 및 최종 좌표 보존, 근접 잔기 표시, 반복 버튼의 상태 유지, CCD STI 카드 조회와 취소 시 연출 정리를 Unity batch에서 확인했습니다. 실제 Solar 후보 추천은 imatinib·dasatinib·nilotinib 카드로 반환됐고, 번호 선택은 수용체를 바꾸지 않고 dasatinib 후보 로더로 연결됐습니다. 마이크를 통한 실제 발화 입력 및 XR 기기 조작은 별도 확인이 필요합니다.
