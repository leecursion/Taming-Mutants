# 사건 마무리 서술퀴즈

도킹 성공 뒤 학습자가 이유를 자기 말로 설명하고, 비서가 그 설명의 근거를 짚습니다.
음성 인식 결과는 바로 채점하지 않습니다. 연구 노트에서 학생이 내용을 읽고 수정한 다음
「이 설명 보내기」를 누릅니다. 수정과 재녹음은 학습 재시도 횟수를 소모하지 않습니다.

## 플레이 흐름

1. 단계 완료 도킹 성공 → 기존 해설과 CFTR/p53 연출 종료를 기다립니다.
2. 질문 → 연구 노트에 질문과 안내가 남습니다. 기존 마이크 또는 직접 입력을 사용합니다.
3. 답변 확인 → 인식 결과를 고치거나 다시 입력할 수 있습니다. 확인 버튼을 눌러야 채점합니다.
4. 이유 확인 → LLM은 실제 학생 답변에서 짧게 인용하여 피드백합니다.
5. 개념 복습 → 알려진 개념이 빠졌으면 해당 단계로 이동합니다.
6. 보완 질문 → 단계 설명과 카메라 이동이 끝난 뒤, 그 개념만 묻는 질문을 합니다.
   재시도 채점은 이전 답변과 새 설명을 함께 고려하므로 이미 설명한 내용을 반복할 필요가 없습니다.
7. 마무리 → 결과 노트를 보여주고 복습 전 성공 단계로 돌아갑니다.
   노트는 직접 닫거나 20초 뒤 자동으로 닫힙니다.

## 학생에게 보여주는 결과

| 결과 | 뜻 |
|---|---|
| 내 설명으로 이해를 확인했어요 | 첫 답변에서 이해 근거를 확인했습니다. |
| 복습한 내용을 연결해서 설명했어요 | 복습 후 답변으로 이해를 확인했습니다. |
| 함께 핵심을 정리했어요 | 재시도를 소진해 모범답안을 함께 읽었습니다. 이해 확인으로 기록하지 않습니다. |
| 이번 답변은 확인하지 못했어요 | 서버·응답 문제 또는 근거 부족으로 판정할 수 없습니다. |
| 이번 설명은 건너뛰었어요 | 학생이 넘어가기를 선택했거나 답변 대기 시간이 끝났습니다. |

확인 실패와 통과를 구분하지만 어느 경우에도 게임 진행을 막지 않습니다.
결과와 답변은 현재 실행의 메모리에만 남으며 파일 저장·외부 통계 전송은 추가하지 않았습니다.
화면의 인용문 검사는 「실제로 한 말인가」를 확인할 뿐, LLM 해석의 교육적 정확성을 보증하지 않습니다.

## 설정

- AIAssistantBrain.useOralCheck: 전체 기능 사용 여부.
- maxOralRetries: 학습 복습 횟수. 기본 1회, 실행 시 0~3회로 제한합니다.
- allowTypedOralAnswersWithoutMicrophone: 마이크 없는 PC에서 직접 입력만으로 참여.
  기본 꺼짐이며, 끄면 음성 미설정 시 기존처럼 건너뜁니다.
- QuestDefinition.oralCheck: 질문, 채점 기준, 개념별 복습 단계·retryQuestion, 모범답안.
  기본 5개 사건에 10개 개념별 후속 질문이 들어 있습니다.
- OralCheckClient: 기존 AICoScientistClient의 프록시 URL 마지막 경로를 oral-check로 바꾸고
  공유 토큰을 물려받습니다. 씬 편집 없이 실행 시 자동 부착합니다.
- 연구 노트는 PC에서 화면 왼쪽에 나타납니다. XR 활성화 시 World Space로 전환합니다.
  XR 레이 입력과 한글 폰트는 실제 기기에서 별도 확인해야 합니다.
- 별도 패키지 설치는 없습니다. 이미 프로젝트에 있는 Newtonsoft.Json으로 응답을 검증합니다.

## 서버 계약

POST /api/oral-check

입력: questId, criteria, answer, conceptKeys, previousAnswer.
응답: understood, missingConcept, followUp, evaluated, evidence.

- criteria 2,000자, answer 1,000자, previousAnswer 2,000자로 제한합니다.
- conceptKeys에 없는 키는 복습 이동에 사용하지 않습니다.
- evidence가 현재/이전 답변에서 실제로 나온 말인지 서버와 클라이언트가 각각 확인합니다.
  대조할 때는 양쪽에서 글자와 숫자만 남깁니다 — 모델이 인용을 옮기며 띄어쓰기나
  문장부호를 바꾸는 일이 잦아, 글자 그대로 대조하면 제대로 설명한 학습자가
  표기 차이만으로 채점 불가가 됐습니다. 없는 말을 지어낸 인용은 여전히 걸립니다.
- evaluated=false는 확인 불가입니다. understood=true라도 이해했다고 표시하지 않습니다.
- 구 버전 서버의 evaluated 없는 응답도 확인 불가로 처리합니다.
- 채점 불가로 떨어질 때마다 서버가 이유를 로그에 남깁니다(상류 실패, JSON 파싱 실패,
  필드 누락, 없는 인용, 근거 없는 통과). `npx wrangler tail`로 확인합니다.
  이유를 남기지 않으면 밖에서는 모든 실패가 똑같은 응답으로만 보입니다.

## 안정성

답변 대기는 기본 60초입니다. 녹음·변환·수정 중에는 시간을 늘리되 한 답변당 총 180초를
넘기지 않습니다. 조용히 읽고만 있는 경우는 최초 60초 상한이 적용됩니다.
질문과 복습 설명은 6프레임 연속 대사·카메라·연출 완료를 확인합니다(상한 40초).
이전/Esc, 사건 변경, 비서 비활성화 시 대기와 전환 잠금을 해제하고 채점·음성 변환도 취소합니다.
퀴즈 실행 번호가 바뀌면 이전 실행에서 도착한 입력과 채점 결과를 무시합니다.
CFTR 교정제 중간 성공에는 질문하지 않습니다.

QuestSession이 있는 씬에서는 기존처럼 DockingQuestCatalog가 다음 사건으로 자동 전환하지 않습니다.
단독 도킹 씬의 전환은 owner별 잠금으로 보류합니다. 기존 씬과 다른 작업의 사실 컨텍스트는 유지합니다.

## 자동 검증

프로젝트 루트에서 실행:

    node --test server/oral-check.test.mjs
    powershell -ExecutionPolicy Bypass -File Tests/OralCheck/run.ps1

서버 11개 테스트: 인증, 잘못된 입력, 통과, 복습, 알 수 없는 개념, 가짜 인용,
인용 표기 차이, 이전 답변 반영, 코드 펜스, 길이 제한, 서버 오류.
C# 36개 검사: 음성 초안 확인, 수정, 중복 전송, 취소 후 입력, 시간 연장·상한,
누락·중복·잘못된 타입의 JSON, 실제 인용 검증, 구 버전 서버 처리.
전체 런타임 스크립트는 Unity 6000.0.79f1 컴파일러와 프로젝트 참조로 컴파일했습니다.
이후 프로젝트는 6000.5.3f1로 올라갔고, 인용 대조 완화분은 .NET 8 테스트 프로젝트로만
컴파일했습니다 — 에디터에서 한 번 열어 전체 컴파일을 확인해 주세요.
자동 테스트는 실제 LLM 채점 정확도나 Unity 화면 조작을 검증한 것이 아닙니다.

## 대회 시연 리허설

ABL1 사건을 사용하면 전후 차이를 짧게 보여줄 수 있습니다.

1. 도킹 성공 후 연구 노트가 열리는지 확인합니다.
2. 「문지기가 커졌어요」라고 말한 뒤 인식된 문장을 일부러 수정해 제출합니다.
3. 공간과 약 모양의 연결이 빠졌다는 피드백 → 해당 단계 복습 → 짧은 보완 질문을 확인합니다.
4. 「가느다란 연결 부분으로 커진 문지기를 피해서 들어갔어요」라고 덧붙입니다.
5. 「복습한 내용을 연결해서 설명했어요」와 실제 답변 인용이 나오는지 확인합니다.
6. 같은 흐름에서 서버를 끊어도 「확인하지 못했어요」로 마무리하며 진행 가능한지 확인합니다.

추가 Play 모드 확인:
- 말풍선·마이크·노트가 서로 가리지 않는지, 1280×720/1920×1080에서 한글이 잘리지 않는지.
- 음성 확인 안내 중 재녹음하여 스피커 음성이 섞이지 않는지.
- 확인·채점·복습 각각에서 이전/Esc/넘어가기를 눌러 남은 대사나 응답이 끼어들지 않는지.
- CFTR 교정제는 건너뛰고 potentiator 완료 뒤에만 질문하는지.
- 정상 답변, 일상적 비유, 실제 오개념, 정정 답변을 사건별로 여러 번 채점해 일관성을 확인합니다.

실제 Unity Play 모드, 실제 마이크와 LLM, XR 기기의 전체 흐름 검증은 아직 수행하지 않았습니다.
